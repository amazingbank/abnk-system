- **实测修正与坑位归档**（三处，均已回写 Dockerfile 注释）：
  1. **Flutter 官方 stable Linux 归档仅 x64**（releases_linux.json 实测 3.47.x 无 arm64）——mweb builder 固定 `--platform=linux/amd64`（本地 Apple Silicon 经 Docker Desktop Rosetta 模拟，服务器 x86_64 原生）；runtime 层不受影响
  2. **SDK 归档属主坑**：tar 保属主 → git dubious ownership（exit 128）→ `tar --no-same-owner` + `git safe.directory` 双保险
  3. **依赖分层坑**：`openapi` 为路径依赖（openapi-generated/）需随 pubspec 前置 COPY；BuildKit cache mount 仅单 RUN 可见——`flutter build web` 步骤补挂同一 pub cache（否则 dart2js 报 vector_math 等 No such file or directory）
- **API 基址口径实测修正**（对计划「相对路径」的修正，两处 Dockerfile 注释归档）：P3.1/P3.2 客户端契约均要求/支持绝对基址（mobile `GeneratedClient._normalizeBaseUrl` 强制绝对 URL 且生成路径已含 `/login` 与 `/abnk/api/v1` 全前缀；BO generatedClient 绝对基址 = 跨 origin 直连）——统一注入网关 origin `https://api.amazingbank.ai`，经入口 nginx api Host 分流直达网关；跨 origin 由网关 CorsConfig 放行（P3.1 web 载体同机制已实测）

## 四、调试插曲（根因与修复记录）

- 症状：首验 VP2.1.4 返回 404，响应体为 Tomcat/10.1.59 HTML 样式（非网关自身 Spring JSON 404）——请求已转发至 Fineract，但路径不被识别。
- 直连对照：`curl http://localhost:8081/fineract-provider/api/v1/offices`（双头）→ 200，排除 Fineract 侧问题。
- 取证：一次性 Python 假后端（:8099）抓包，分别用无 path base 与含 path base（`http://127.0.0.1:8099/fineract-provider`）各验证一轮——后者收到的请求行仍为 `GET /api/v1/offices`。
- 根因：Spring Cloud Gateway（Spring Cloud 2025.0 线）实际转发时**忽略 route URI 的 path 部分**，`/fineract-provider` context path 被丢弃。
- 修复：路由过滤器改为 `StripPrefix=1` + `PrefixPath=${ABNK_FINERACT_PREFIX:/fineract-provider}`；`ABNK_FINERACT_BASE` 语义调整为 host:port（如 `http://localhost:8081`，服务器形态 `http://abnk-fineract:8080`），context path 独立经 `ABNK_FINERACT_PREFIX` 覆盖。
- 清理：临时 TRACE 日志（org.springframework.cloud.gateway）与探针假后端已全部移除，清理后重启复验双通道 200（见上）。
